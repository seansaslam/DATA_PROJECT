Database connections

Each application database is configured independently — its own type, server, credentials and port. Nothing else in the app branches on connection type, so you can move ProCount to Azure SQL and leave the Well Master on the local SQL Server, and every page, load strategy and document keeps working. Credentials are stored in the app's local SQLite file (app_state.sqlite3), not in source.

Enabling CDC on SQL Server. The service account is db_owner, which covers all of Change Tracking, but sys.sp_cdc_enable_db needs sysadmin. Run once per database:
USE [PROCOUNT_DB];
EXEC sys.sp_cdc_enable_db;
CDC also needs SQL Server Agent running — the capture job is what fills the change tables. Azure SQL Database needs neither: db_owner can enable CDC itself and the capture runs as a managed process.
